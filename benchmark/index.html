    Platform check (0.3.35, 2026-11-10)¶

    AbstractVision 0.3.35 was installed from scratch on three machines and asked to generate images at each model's catalog defaults. "Warm" is the second generation with the model resident in the same process. Times are wall clock for the generation call; the load time is given separately.

    The three machines¶

    Linux, processor only Linux NVIDIA Apple silicon laptop
    Hardware 6 cores, 11 GB RAM (about 3 GB free), no GPU, Python 3.14 Quadro RTX 5000 16 GB (Turing, compute capability 7.5), 4 vCPU, 26 GB RAM Apple silicon, Metal (MLX)
    Install torch torchvision from the CPU index, then abstractvision[gpu] (1.4 GB) abstractvision[gpu] (5.7 GB, no compiler) abstractvision[apple]
    Device and dtype picked cpu, float32 cuda, float16 (the card has no native bfloat16) Metal, MLX quantized weights

    What the table says: on the NVIDIA card the Diffusers models load once and stay resident, the second generation reuses them, and unload returns the GPU memory (the process keeps only the CUDA context); the GGUF path through sd-cli reloads the model on every call. Models trained in bfloat16 (Z-Image, OmniGen) give black images in float16 on a card without native bfloat16: run them in float32 there, or use their GGUF variant. The processor path works with the same API and is for small models or patience. Gated repositories (FLUX.1, FLUX.2 [klein] 9B and dev, Stable Diffusion 3) need a Hugging Face token and were not part of this check; Wan 2.2 video is disabled on the Diffusers backend and refuses with a clear message.

    Methodology: clean virtual environments, models downloaded by the package, nvidia-smi sampled every 0.25 s during the GPU runs, output images checked for pixel variance. The per-model raw results of the NVIDIA run are kept with the release notes of 0.3.35.
